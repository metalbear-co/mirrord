# mirrord-beyond

Set up and use mirrord Beyond: run a local process against services deployed outside Kubernetes, such as Amazon ECS tasks, through the MetalBear Cloud sessions-manager.

## What it does

This skill helps AI agents with both sides of mirrord Beyond:

- **ECS setup** (platform teams): store the serverless agent API key in AWS Secrets Manager without it ever passing through the chat, merge the mirrord remote bootstrap into an existing ECS task definition (Fargate or EC2), deploy after the user's go-ahead, verify the task registers, and hand developers a ready `mirrord-up.yaml`
- **Developer sessions**: sign in with `mirrord login`, write a `mirrord-up.yaml` with a `serverless/` target (or an IDE `mirrord.json`), run `mirrord up`, and send requests with the session header
- **Troubleshoot** across both sides: name and organization mismatches, secrets the task can't read, bootstrap and glibc problems, sessions that go through the Operator by mistake
- **Rotate** the API key with a grace window

## Example prompts

```
"Set up mirrord Beyond for our orders ECS service"

"Add the mirrord remote bootstrap to this task definition and deploy it"

"Rotate our mirrord serverless agent key"

"Debug the orders service on ECS locally with mirrord"

"Write a mirrord-up.yaml for the payments serverless target"

"mirrord up says it timed out connecting to the serverless target's agent"
```

## Prerequisites

- **ECS setup:** an ECS service on Linux, with an image based on glibc 2.30 or later (not Alpine), an execution role, and outbound HTTPS from its tasks; the AWS CLI with permission to manage Secrets Manager, IAM role policies and the ECS service; `jq`; and the organization's serverless agent API key, generated by an organization admin at [app.metalbear.com](https://app.metalbear.com)
- **Developer sessions:** mirrord CLI 3.288.0 or later, and a MetalBear account in the same organization

The MetalBear Cloud mode is available on every plan, including Free, while in alpha.

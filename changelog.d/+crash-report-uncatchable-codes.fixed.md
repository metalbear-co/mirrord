The Windows crash report now explains a heap corruption (`0xC0000374`) the same way it already explained a fast-fail, and it gives the recipe for capturing a dump after any crash the in-process handler could not see. Both codes end the process without running a handler, so the report said "no memory dump is available" and, for heap corruption, offered nothing further. It now names page heap as the tool that finds the offending write, and notes that the process which dies is often not the one that damaged the heap.

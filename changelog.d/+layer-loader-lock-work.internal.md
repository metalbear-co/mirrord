The Windows layer no longer does loader-unsafe work inside `DllMain`. The early process and module snapshot, which walks every process on the machine and opens each loaded module on disk, and the mirrord-console logger, which opens a socket, both moved to the worker thread that runs after `DllMain` returns. `layer-win` also gained a `clippy.toml` that rejects `std::thread::current`, `std::thread::park`, `std::io::stderr` and `std::io::stdout`, which all end the process when a hook reaches them.

Runs that hit a wall on the way to the operator now report which one as `operator_wall`: a target type or `copy_target` that needs it, `operator: true` with no operator in the cluster, an expired license, the multi-pod and HTTP-filter warnings, `split_queues` or `db_branches` set without it, the queue-splitting hint, and the `preview`, `ci api-key`, `operator status`/`session` and `ls` commands that stop without it. Only the first wall a run meets is kept, and the proxy that reports the session carries it, so walls on runs that go on are counted too.

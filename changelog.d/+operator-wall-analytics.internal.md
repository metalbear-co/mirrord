Runs that hit a wall on the way to the operator now report which one as `operator_wall`: an operator-only target type or `copy_target` (including when rejected with `operator: false`), `operator: true` with no operator in the cluster, an expired license, a deleted agent pod, the multi-pod and HTTP-filter warnings, `split_queues`, remote `db_branches`, `tls_delivery`, `on_concurrent_steal` or `multi_cluster` set without it, the queue-splitting hint, and the `preview`, `ci api-key`, `operator status`/`session` and `ls` commands that stop without it. Only the first wall a run meets is kept, and it is handed to the proxy that reports the session, so walls on runs that go on are counted too.

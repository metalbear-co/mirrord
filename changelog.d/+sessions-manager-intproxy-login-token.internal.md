Authenticate the intproxy to a standalone sessions-manager with the developer's `mirrord login` token instead of the API-key exchange, which stays with agents. The token is read from the token store for the cloud set by `MIRRORD_METALBEAR_CLOUD_URL` (the latest login when there are several organizations) whenever the intproxy or external proxy (re)connects, so it never travels in their environment and a reconnect picks up a newer login. It is sent only over HTTPS or to a sessions-manager on localhost; over plain HTTP to another host the session goes out without it. The CLI warns when there is no usable login or the token would be left off, a refused login points at `mirrord login` (and at `MIRRORD_SESSIONS_MANAGER_AUTH_TOKEN` when a shared secret is configured), and `mirrord login` reads `MIRRORD_METALBEAR_CLOUD_URL` too, so it logs in to the same cloud. A sessions-manager reached through the operator is unaffected.

Fixed the Windows layer giving a DNS result it allocated to `ws2_32` to free, which corrupts the process heap (`0xC0000374`). `ws2_32` frees `ADDRINFOA` through `freeaddrinfo` and `ADDRINFOW` through `FreeAddrInfoW`, and only the second one was hooked. So every caller of the `ADDRINFOA` resolver — the one most native programs use — handed a chain allocated by Rust to the wrong allocator on free, and left the layer's record of that chain behind for a later chain at the same address to trip over. `freeaddrinfo` now has its own hook.

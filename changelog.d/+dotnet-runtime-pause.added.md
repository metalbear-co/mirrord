Experimental: `mirrord up --debug <service>` also holds each .NET program the service starts, such as the app under `dotnet run`, before any of its .NET code runs, until an IDE attaches its debugger and releases it. This needs .NET 5 or later. Every session, debugged or not, now also leaves the target's .NET diagnostic-port variables out of the local program's environment: `DOTNET_DiagnosticPorts`, `COMPlus_DiagnosticPorts` and both spellings of `DefaultDiagnosticPortSuspend`. They name sockets inside the pod, and one that says `suspend` could keep a local .NET program paused. A value you set locally, in an env file or in `env.override` still applies.

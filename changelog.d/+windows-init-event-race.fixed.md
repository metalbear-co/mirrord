Fixed the Windows layer ending a process it had just been injected into, with "No init event found for pid ...". The parent creates the readiness event immediately before it injects the layer and drops it as soon as its wait ends, but the layer opened that event later, on its worker thread. A worker that lost that race found nothing and ended the target, which for a development server means the server dies. The layer now claims the event while `DllMain` runs, which is the last moment the parent is certain to still hold it, and a process nobody is waiting for runs normally instead of ending.
